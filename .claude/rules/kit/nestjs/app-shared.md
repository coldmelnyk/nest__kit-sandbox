# `app/` и `shared/`

## Что лежит в `src/`

- `main.ts` — запуск API;
- `seed.ts` — запуск сидов, без HTTP (`seeds.md`);
- `app/` — сборка приложения;
- `core/`, `modules/` — модули, по папке на модуль (`modules.md`);
- `shared/` — общее без предметной области;
- `generated/` — сгенерированный код: создаётся инструментом, руками не правится, в git не попадает.

`shared/` не импортирует ни модули, ни `app/`. Модули не импортируют `app/`.

## `app/` — только сборка

Здесь то, что знает обо всех модулях сразу:

- `app.module.ts` — список модулей;
- `app.setup.ts` — префикс маршрутов, валидация, фильтр ошибок, документ API;
- `error-statuses.ts` — реестр таблиц статусов всех модулей (`errors.md`);
- `app-ports.module.ts` — связи обратных зависимостей (`ports.md`);
- `seed.module.ts`, `seeds.ts` — сборка и список сидов (`seeds.md`).

Логики, DTO и помощников в `app/` нет. Всё, что нужно модулям, — в `shared/`.

## `shared/` — общее без предметной области

Здесь живут реализации ролей kit: время, id, журнал, конфигурация, формат ошибок, список с курсором, база (если подключён аддон), основа сидов, проверка здоровья. Конкретные пути — в `.claude/kit.json`.

Роли объявлены глобально: модуль внедряет их через конструктор и не импортирует в своём `*.module.ts`.

В `shared/` можно положить код, только если выполнены все три условия:

1. В нём нет предметной области: ни названий сущностей, ни их таблиц, ни их правил.
2. Он полезен любому модулю, а не одному. Нужное одному модулю остаётся в модуле.
3. У него своя подпапка. Файлов в корне `shared/` нет, папки `utils` нет.

Подпапки `shared/` могут импортировать друг друга: например, HTTP-часть пользуется журналом.

## Проверяется автоматически

- `lint-boundaries`: `shared/` импортирует только `shared/` и `generated/`; модули не импортируют `app/`.
- `lint-roles`: библиотека журнала — только в реализации журнала и точках входа.

## Не проверяется

- Предметная область в `shared/` и логика в `app/`.
- Файлы глубже двух уровней вложенности: линт границ их не видит.
