# Конфигурация — `ConfigService`

Что считается секретом и как поступать при утечке — `base/secrets.md`.

## Роль

- **Зачем.** Приложение не стартует с неверной конфигурацией, а код не читает окружение где попало.
- **Контракт.** Проверяет все переменные при старте и отдаёт их типизированными.
- **Где.** Схема и проверка — `src/shared/configs`.
- **Запрещено:** `process.env` в `src/` вне `src/shared/configs`. Вне `src/` окружение читают конфиги инструментов и тесты.

## Окружения

| `NODE_ENV` | Файлы | Где |
| --- | --- | --- |
| `dev` | `.env.local`, затем `.env.dev` | локально и на dev-стенде |
| `production` | `.env.production` | production |
| `e2e` | `.env.e2e` | тесты; в CI — переменные задачи |

В git — только `.env.example`.

## Новая переменная

Добавляется сразу в три места:

1. Схема конфигурации — с проверкой. Приложение не стартует, если переменной нет или она неверна.
2. `.env.example` — с безопасным значением. У секрета значение пустое и подсказка, где его взять.
3. Конфиг e2e — выдуманное значение, если переменная обязательна.

Обязательную переменную, без которой не стартует production, сообщают владельцу инфраструктуры до слияния PR.

## Типы значений

- Пустая строка означает «не задано». Число, для которого `0` — допустимое значение, отдельно проверяется на «задано»: иначе пустая строка превратится в `0`.
- Логическая переменная — строка `true` или `false`, проверенная явно. Неявное приведение типов не используется: строка `"false"` при нём становится `true`.
- Переменная, разрешённая только в одном окружении, проверяется дважды: схема не даёт стартовать с ней в другом окружении, а модуль читает её только в своём.
- Переменная для инструмента, а не для приложения (например `FORCE_COLOR`), вносится в `.env.example` и в список исключений проверки `env-example`.

## Проверяется автоматически

- Старт приложения: схема отклоняет отсутствующую или неверную переменную. Обязательная переменная, забытая в конфиге e2e, роняет e2e на старте.
- `env-example`: в `.env.example` есть каждая переменная схемы, лишних и повторов нет.
- `lint-roles`: `process.env` в `src/` только в `src/shared/configs`.

## Не проверяется

- Что число, для которого `0` допустим, проверено на «задано».
- Что владельцу инфраструктуры сообщили о новой обязательной переменной.
