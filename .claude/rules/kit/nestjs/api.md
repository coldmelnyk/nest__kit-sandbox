# API

## Маршруты

- Ресурс — во множественном числе и kebab-case: `/invoices`, `/price-lists`.
- Параметр пути назван по сущности: `:invoiceId`, а не `:id`.
- Данные текущего пользователя — под `/me`. Его id берётся только из сессии и не передаётся ни в пути, ни в query, ни в теле.
- Переход состояния, который не сводится к правке поля, — `POST` на глагол: `/invoices/:invoiceId/void`. Правка полей — `PATCH`.

## Доступ

- Открытый эндпоинт помечается `@Public()`. Без пометки эндпоинт закрыт.
- Как устроены сессия, вход и проверка прав, решается вместе с модулем, который их вводит. Тогда же в это правило дописывается раздел «Авторизация». До этого закрытых эндпоинтов не появляется.

## Коды ответа

| Операция | Код | Тело |
| --- | --- | --- |
| `GET` | 200 | ресурс или список |
| `POST`, создавший запись | 201 | созданная запись |
| `POST`-действие с новым состоянием | 200, `@HttpCode(200)` | новое состояние |
| `POST`-действие без нового состояния (отправить код, выйти) | 204, `@HttpCode(204)` | нет |
| `PATCH` | 200 | обновлённая запись |
| `DELETE` | 204, `@HttpCode(204)` | нет |

Если у операции есть новое состояние, оно возвращается в теле: клиенту не нужен второй запрос.

## DTO

Всё, что сервер принимает и отдаёт, описано DTO. Ответ из объекта без DTO — ошибка.

- DTO одной сущности — в одном `namespace` в файле `presentation/dto/<сущность>.dto.ts`.
- Внутри: сама сущность без суффикса (`Invoice.Card`), тело запроса — `<Что>Request`, ответ — `<Что>Response`.
- У каждого класса `@ApiSchema({ name: '<Namespace>-<Класс>' })`: одинаковые имена классов иначе перезапишут друг друга в документе API.
- Поля запроса проверяются декораторами `class-validator`. Каждое поле описано `@ApiProperty` или `@ApiPropertyOptional`.
- Вложенный объект в запросе — `@ValidateNested()` и `@Type(() => …)`, иначе его поля не проверяются.
- Метод контроллера указывает DTO и в `@ApiOkResponse({ type })`, и в типе возврата: без типа возврата компилятор не сверит ответ с DTO.
- У метода `@ApiOperation({ summary })`, у контроллера `@ApiTags`.
- Каждый статус ошибки, который может вернуть метод, описан с телом `ErrorResponse`. Метод со входом — путь, query или тело — описывает 400.

```ts
export namespace Invoice {
    @ApiSchema({ name: 'Invoice-Card' })
    export class Card {
        @ApiProperty({ example: '0193a4b2-5c6d-7e8f-9a0b-1c2d3e4f5a6b' })
        id: string;

        @ApiProperty({ type: String, nullable: true, example: null })
        voidedAt: Date | null;
    }
}

@Get(':invoiceId')
@ApiOperation({ summary: 'Read one invoice' })
@ApiOkResponse({ type: Invoice.Card })
@ApiBadRequestResponse({ type: ErrorResponse })
@ApiNotFoundResponse({ type: ErrorResponse })
read(@Param('invoiceId', ParseUUIDPipe) invoiceId: string): Promise<Invoice.Card> {
    return this._invoices.read(invoiceId);
}
```

## Имена полей

Поля запросов и ответов — в camelCase и совпадают с полями модели данных. Если имя или значение в ответе отличается от модели, его преобразует маппер `presentation/mappers/<модель>.mapper.ts`, а не декораторы сериализации.

## Списки

- Запрос: `limit` от 1 до 100, по умолчанию 20, и `cursor` из прошлого ответа. DTO запроса наследует `ListQuery`. Фильтры — явные query-параметры.
- Ответ: `items` и `nextCursor`. `null` в `nextCursor` — страниц больше нет. Общего числа записей нет.
- Порядок фиксирован: `createdAt desc, id desc`. Параметра сортировки нет.
- Запрос берёт `limit + 1` запись; лишняя отрезается и показывает, есть ли следующая страница.
- Условие курсора начинается с границы по первому полю сортировки: `createdAt <= :at AND (createdAt < :at OR id < :id)`. Без неё база не может пройти по индексу и читает лишние строки.
- Нужен индекс по полям фильтра и сортировки.
- Курсор разбирает одна общая функция. Испорченный курсор — 400 `INVALID_CURSOR`.

## Проверяется автоматически

- `tsc`: ответ совпадает с DTO, если у метода указан тип возврата.
- Глобальная валидация: лишние поля запроса отбрасываются, границы `limit` проверяются.
- `openapi-contract`, по тому же документу API, что получает клиент:
    - у каждой операции есть `summary`, тег и уникальный `operationId`;
    - успешный ответ ровно один и ссылается на DTO, у 204 тела нет;
    - каждая описанная ошибка ссылается на `ErrorResponse`;
    - 400 описан у каждой операции со входом;
    - параметры пути названы и имеют схему;
    - ни одна схема, кроме enum, не пуста.

## Не проверяется

- Стиль маршрутов и коды ответа, `@HttpCode` у действий и удаления.
- Пометка открытого доступа там, где эндпоинт должен быть закрыт.
- Тип возврата у метода контроллера.
- Описание ошибок, кроме 400: проверка видит только описанное.
- Совпадение имён в `@ApiSchema`: одна схема молча заменяет другую.
- `limit + 1`, граница курсора и индекс у списка.
