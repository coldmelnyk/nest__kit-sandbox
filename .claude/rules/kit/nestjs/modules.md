# Модули и границы

## Виды модулей

- **Ядро** — `src/core/<модуль>/`: на него опираются прикладные модули.
- **Прикладные** — `src/modules/<модуль>/`: возможности продукта.

Список модулей пока пуст. Каждый новый модуль вносится сюда в свой список — вместе с PR, который его создаёт.

Направление зависимостей: `app → modules → core → shared`. Прикладные модули друг от друга не зависят. Ядро о прикладных модулях не знает.

## Зависимости ядра от ядра

Разрешены только те, что перечислены ниже. Сейчас таких нет.

Новая зависимость ядра от ядра — вопрос владельцу проекта. После ответа она вносится сюда строкой `<кто> → <от кого>: зачем`.
Импорт только типов цикла не создаёт.

## Публичный интерфейс

Всё, что модуль открывает другим, экспортируется из его `index.ts`: класс модуля, сервисы, порты для других модулей, типы входа и результата, таблица статусов ошибок. Остальное закрыто. Другие модули и `app/` импортируют только `index.ts`.

```ts
export { InvoicesModule } from './invoices.module.ts';
export { InvoiceIssuingService } from './application/services/invoice-issuing.service.ts';
export type { InvoiceView } from './domain/entities/invoice.entity.ts';
export { INVOICES_ERROR_STATUSES } from './presentation/invoices.error-statuses.ts';
```

## Владение данными

Модуль владеет своими таблицами, и только его код к ним обращается. Чужие таблицы другой модуль читает и меняет только через интерфейс владельца.
Как это выглядит в схеме базы — в правилах аддона базы данных.

## Как модули взаимодействуют

- **Синхронно** — вызов интерфейса другого модуля в той же транзакции: транзакция передаётся первым параметром.
- **Отложенно** — задание, поставленное в той же транзакции. Последствия в другом прикладном модуле — всегда задание.
  Очереди заданий в проекте пока нет: задача, которой она понадобится, начинается с вопроса владельцу проекта.
- Внутри транзакции нет сетевых вызовов, кроме базы.
- Обработчик задания идемпотентен: задание может прийти больше одного раза.

```ts
return this._transactions.run(async (tx) => {
    const invoice = await this._invoices.lockById(tx, invoiceId);
    invoice.void(this._clock.now());
    await this._invoices.save(tx, invoice);
    await this._payments.cancelPending(tx, invoiceId);
});
```

## Взаимная зависимость модулей ядра

Если двум модулям ядра нужны друг друга, одно из направлений идёт через порт, а связь стоит в `src/app/app-ports.module.ts` (`ports.md`).

## Проверяется автоматически

- `lint-boundaries`:
    - снаружи модуля импортируются только `index.ts` модулей ядра, `shared/` и `generated/`;
    - прикладной модуль не импортирует другой прикладной, ядро не импортирует прикладные;
    - `app/` берёт из модулей только `index.ts`;
    - циклы импортов.
- `lint-config-sync`: конфиг линта собран скриптом и руками не правлен.
- Владение таблицами — проверки аддона базы данных (`table-ownership`).

## Не проверяется

- Сетевой вызов внутри транзакции; идемпотентность обработчика задания.
- Зависимость ядра от ядра, о которой не спросили владельца.
