# Сиды

Сид — выдуманные данные для окружения `dev`: локальная база и dev-стенд. В `production` сидов нет.

## Команда

- `npm run seed` собирает проект и запускает сиды; `npm run seed:built` запускает уже собранное — так команда работает на стенде.
- Команда работает только при `NODE_ENV` `dev` и `e2e`. В `production` она ничего не пишет и завершается с кодом 1.
- Сиды запускаются по порядку списка. Первый упавший останавливает запуск с кодом 1.

## Сид модуля

- Данные добавляет модуль-владелец. Сид — класс в `application/seeds/<что>.seed.ts`, наследник `DevSeed`.
- Имя сида — `<модуль>.<что>`: `billing.demo_invoices`. Два сида с одним именем не запускаются.
- Сид — провайдер своего модуля, открыт через `index.ts` и внесён в общий список `src/app/seeds.ts`.
- В списке — только импорты и массив классов. Порядок массива — порядок запуска: сначала то, на что ссылаются другие.
- Сид пишет через сервисы своего модуля, а не запросами в обход: действуют те же правила entity, время и id из ролей.
- Повторный запуск безопасен: сид проверяет, есть ли его данные, и не создаёт дублей.
- Данные выдуманы, и это видно: `demo@example.com`. Настоящих людей, телефонов и адресов нет.
- На данные чужого сида ссылаются константой, которую владелец открыл в своём `index.ts`. Литералы чужого сида не повторяются.
- Пароль сида приходит из переменной окружения (`config.md`), а не пишется в коде.

```ts
@Injectable()
export class DemoInvoicesSeed extends DevSeed {
    readonly name = 'billing.demo_invoices';

    constructor(private readonly _invoices: InvoiceIssuingService) {
        super();
    }

    async run(): Promise<void> {
        if (await this._invoices.existsByNumber(DEMO_INVOICE_NUMBER)) {
            return;
        }
        await this._invoices.issue({ number: DEMO_INVOICE_NUMBER, customerId: DEMO_CUSTOMER_ID, amountCents: 12_500 });
    }
}
```

## Проверяется автоматически

- `seed-registry`: каждый сид из `*.seed.ts` есть в списке, лишнего и повторов нет.
- unit: команда отказывается работать в `production`.
- e2e запуска: порядок, остановка на первом упавшем, отказ при одинаковых именах.
- Запуск команды: каждый сид из списка — провайдер какого-то модуля.

## Не проверяется

- Что повторный запуск не создаёт дублей.
- Что сид пишет через сервисы, а не напрямую в таблицы.
- Логика в списке сидов; имя сида с префиксом чужого модуля.
- Настоящие персональные данные в сидах.
