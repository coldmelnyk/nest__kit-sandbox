# Тесты NestJS

Общая политика — `base/testing.md`. Здесь — раскладка и оснастка стека.

## Раскладка

```
test/
  unit/<тема>/*.spec.ts          без базы и без приложения Nest
  e2e/<тема>/*.e2e-spec.ts       настоящая база; через HTTP, если у модуля он есть
  factories/                     фабрики данных, файл на модуль
  utils/                         оснастка и двойники портов
  setup/                         глобальная подготовка e2e: миграции
```

`npm test` — unit, `npm run test:e2e` — e2e.

## Что чем проверять

- **Правила entity** — unit, без Nest и базы, на фиксированных датах.
- **Эндпоинт** — e2e: успешный путь и каждая ошибка со статусом и `code`.
- **Сценарий модуля без HTTP** — e2e через его сервисы на настоящей базе: успешный путь и ошибки, которые решают сервис и база (не найдено, занято, чужое, нарушен порядок). Ошибка правила entity остаётся в unit.
- **Список** — e2e проходит все страницы и проверяет, что записи не потерялись и не повторились.
- Запросы, планы и одновременность — в правиле тестов аддона базы данных.

## Оснастка — роли kit

Оснастку пишет проект; kit описывает, что она обязана уметь. Имена и пути — в `.claude/kit.json`.

| Роль | Что умеет |
| --- | --- |
| `useTestApp` | поднимает всё приложение с базой; перед каждым тестом база очищается. Принимает переопределения провайдеров. Для сценариев модулей |
| `createProbeApp` | поднимает тестовый контроллер с настройками приложения, без всех модулей. Нужные модули тест подключает сам. Для общего поведения: фильтр ошибок, журнал, guard |
| `responseBody` | единственный способ прочитать тело ответа в e2e: проверяет, что в нём нет секретов. Поля, которые отдаются намеренно, перечисляются явно |
| `defineFactory` | основа фабрик: значения по умолчанию и переопределения |
| `waitFor` | ждёт результата фоновой работы вместо паузы |

Подмена провайдера — через `useTestApp`:

```ts
const app = useTestApp((builder) => builder.overrideProvider(Clock).useValue(fixedClock));
```

`responseBody` проверяет, что в теле нет полей с секретными именами, JWT, адресов базы и хранилища.

## Ограничения

- Приложение слушает `127.0.0.1` один раз на файл, и HTTP-клиент тестов получает готовый адрес. Если передать ему не слушающий сервер, он откроет порт на каждый запрос, и запрос может попасть в чужой процесс.
- e2e-файлы идут по одному: база общая.
- Время подменяется через `Clock`, без подделки таймеров для дат предметной области.

## Проверяется автоматически

- `lint-roles`: обращение к `.body` ответа в `test/e2e/` запрещено — только `responseBody`.
- `responseBody`: тело ответа без секретов.

## Не проверяется

- Что у эндпоинта есть e2e на каждую ошибку.
- Что правила entity покрыты unit-тестами.
