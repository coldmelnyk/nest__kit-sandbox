# Стиль кода

## Язык

В коде всё на английском: имена, сообщения ошибок, описания в документе API. Текст ошибки для пользователя выбирает клиент по коду.

## Комментарии

Комментарий пишется только там, где из кода не видно, **почему** сделано именно так. Пересказа кода, JSDoc, TODO и закомментированного кода нет.

Директивы отключения линта и `@ts-expect-error` не пишутся: исправляется причина. Если без отключения никак — «Сначала спросить».

## Имена файлов

kebab-case, вид файла — суффиксом через точку: `invoice.service.ts`, `invoice.controller.ts`, `invoice.dto.ts`, `invoice.entity.ts`, `invoice.repository.ts`, `invoice.errors.ts`, `invoice.error-statuses.ts`, `invoice.log-events.ts`, `invoice.spec.ts`, `invoice.e2e-spec.ts`.
Файл без подходящего вида называется по содержимому: `pretty-logs.ts`.

## Имена в коде

- Классы и типы — PascalCase. У entity суффикс `Entity`.
- Константа уровня модуля с фиксированным значением — UPPER_SNAKE_CASE, будь то число, список или таблица: `TIMEOUT_MS`, `LOG_FORMATS`. Единица измерения — в имени.
- Функции и значения, вычисленные при запуске, — camelCase.
- Внедрённая зависимость в поле — с подчёркиванием: `private readonly _events: EventLogger`.
- Чисел и строк «из воздуха» в логике нет: значение выносится в именованную константу в начале файла.

## Импорты и экспорты

- Импорты относительные, с расширением `.ts`. Алиасов путей нет: на относительных путях построены правила границ.
- Тип импортируется через `import type`.
- Экспорты именованные. `export default` — только где его требует инструмент: конфиги, глобальная настройка тестов.

## Функции и классы

- Класс — только для того, что создаёт Nest, а также для entity, ошибок и DTO. Остальное — функции.
- Функция вне класса — стрелочная константа. У экспортируемой функции тип возврата указан явно. Колбэки тоже стрелочные.

```ts
export const isOverdue = (dueAt: Date, now: Date): boolean => {
    return dueAt.getTime() < now.getTime();
};
```

## Типы

- Форма данных — `type`. `interface` — только если его расширяют из других файлов, как реестр событий журнала.
- `any` и `!` не используются. Неизвестное значение — `unknown` и проверка.
- `as` — только на границе с внешними данными: результат `JSON.parse`, тело ответа в тесте, объект из библиотеки без типов. На `as const` это не распространяется.
- `enum` TypeScript не используется. Значения из базы — enum схемы данных и union в `domain/`. Остальные наборы — массив `as const` и union из него.

```ts
const LOG_FORMATS = ['json', 'pretty'] as const;
type LogFormat = (typeof LOG_FORMATS)[number];
```

## «Значения нет»

- Поле есть, но пустое — `null`, как в базе и JSON.
- Необязательный вход — `поле?: T`.
- `undefined` не хранится и не отдаётся в ответе.
- Условие явное: `value === null`, а не `!value`.

## Проверяется автоматически

- `lint-style`: стрелочные функции, запрет `any`, `!` и `console`, явные условия, незавершённые промисы, `type` вместо `interface` (кроме `*.log-events.ts`), запрет `export default` (кроме конфигов и настройки тестов).
- `tsc`: `import type`, расширение `.ts` в импортах.

## Не проверяется

Комментарии и директивы отключения, имена файлов и констант, подчёркивание у зависимостей, уместность `as`, `enum`, `null` вместо `undefined`, алиасы путей.
