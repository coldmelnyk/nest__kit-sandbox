# Документирование

Правило без `paths:`: действует в любой задаче.

Каждое значимое изменение оставляет след в `docs/` в той же ветке, что и код. История в git отвечает на вопрос «что изменилось», `docs/` — «почему так и что из этого следует».

## Где что записывается

| Что произошло | Куда пишется | Когда |
| --- | --- | --- |
| Новая задача, исправление | `docs/tasks/NNN-<slug>.md` по шаблону `_template.md` | до кода; в конце — раздел «Итог» |
| Изменился публичный API: эндпоинт, DTO, код ошибки | раздел «Контракт» задачи | в той же ветке |
| Изменилась схема данных или миграции | задача; несовместимое изменение — ещё и решение `Р-N` | в той же ветке |
| Новая или изменённая переменная окружения, конфигурация | `docs/architecture.md`, раздел «Окружение» | в той же ветке |
| Изменилось устройство: модули, слои, зависимости между ними | `docs/architecture.md` + решение `Р-N` | после подтверждения владельцем |
| Изменилось правило кода или `AGENTS.md` | задача или решение `Р-N`, на которое правило ссылается | в той же ветке |
| Решение об устройстве системы | `docs/decisions.md`, `Р-N` | после подтверждения владельцем; до этого — «Предложено» в задаче |
| Допущение, на котором что-то держится | `docs/decisions.md`, `Д-N` | когда принято |
| Новый термин предметной области | `docs/glossary.md` | когда термин появился в коде |
| Вмешательство вне кода: стенд, данные, инфраструктура | задача с разделом «Итог» | сразу после вмешательства |

Номер задачи — следующий свободный в `docs/tasks/`, три цифры: `012-invoice-void.md`.
Решение `Р-N` записывается только подтверждённым владельцем проекта. Неподтверждённое остаётся в задаче в разделе «Предложено».

## Внутренние изменения

Рефакторинг, тесты, исправление внутри модуля без изменения контракта, данных, конфигурации и устройства записи в `docs/` не требуют. Это решает не автор, а список категорий `docs-check`.

## Проверяется автоматически

- `docs-check` в CI: файл из категории изменён (API, данные, конфигурация, архитектура, правила — пути в `.claude/kit.json`, `packages[].docsCheck`), а в `docs/` изменений нет — PR красный. Исключение — метка `docs:skip` и строка `docs:skip: <причина>` в описании PR.
- `docs-check` в хуке `Stop`: тот же разбор по ветке и рабочему дереву; агент получает напоминание один раз за ход и либо дописывает запись, либо объясняет, почему она не нужна.

## Не проверяется

- Полнота и правдивость записи: `docs-check` видит только, что `docs/` изменён.
- Что запись относится к этому изменению, а не к соседнему.
- Что решение `Р-N` действительно подтверждено владельцем.
