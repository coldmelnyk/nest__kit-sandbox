# Секреты

## Что считается секретом

- токены, коды входа и подтверждения;
- пароли и их хэши;
- ключи внешних сервисов, соли, ключи шифрования;
- адреса базы и внутренних сервисов;
- имена хранилищ, ключи объектов, подписанные ссылки;
- текст ошибок библиотек: в него попадают запросы, адреса и аргументы вызова.

## Где секрета быть не может

Ответы API, подробности ошибок, журнал, примеры в документации API, тестовые данные, коммиты, фронтенд-бандл.

В git — только файл-пример окружения: у секрета в нём пустое значение и подсказка, где его взять. Остальные файлы окружения закрыты `.gitignore`.

В тестах и CI значения выдуманы, и по ним это видно: `e2e-secret-not-a-real-key`.

## Если секрет утёк

1. Секрет считается раскрытым и сразу заменяется.
2. Владельцу проекта сообщают об утечке.
3. Причина утечки устраняется.

Историю git не переписывают: утечку это уже не отменит.

## Проверяется автоматически

Зависит от стека: см. «Проверяется автоматически» в правилах конфигурации, журнала и тестов стека.

## Не проверяется

- Секрет в поле с обычным именем.
- Секрет в примерах документации API.
