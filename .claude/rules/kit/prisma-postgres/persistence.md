# Работа с базой

Транзакции и замки — `transactions.md`. Схема — `schema.md`.

## Подключение — `DbService`

- К базе подключается только `DbService` (`src/shared/db`). Второй клиент Prisma или пул соединений в `src/` не создаётся.
- Сессия базы всегда в UTC, каким бы ни был пояс сервера PostgreSQL. Причина: Prisma отправляет даты текстом в UTC без смещения и отбрасывает смещение при чтении `timestamptz`. В другом поясе время сохранится со сдвигом, а в ночь перевода часов два разных момента сохранятся одинаково.
- Пояс закрепляет `DbService`: дописывает `-c timezone=UTC` последним в параметр `options` адреса базы, сохраняя остальные `options`. При старте он читает пояс сессии и не запускается, если это не UTC.
- `prisma.config.ts` дописывает тот же параметр для сессий миграций. Строки там повторены, а не импортированы: в образ попадает `prisma.config.ts`, но не `src/`. Меняется одно место — меняется и второе.
- `SET TIME ZONE` в запросах и миграциях не пишется. В сыром SQL нет выражений, зависящих от пояса сессии: приведения `timestamptz` к `timestamp` или `date`, `date_trunc` без пояса, литерала времени без смещения. Нужный пояс передаётся явно: `AT TIME ZONE`.

## Владение таблицами

- Модели модуля лежат в `prisma/schema/<модуль>.prisma`, и только код модуля к ним обращается. `shared/` не обращается ни к одной модели.
- Чужие таблицы в запросах запрещены — ни в сыром SQL, ни через связь в выборке.
- Исключение — справочные представления ядра для соединения в запросах. Каждое вносится в список справочных представлений проверки `table-ownership` и разрешает только чтение.
- Внешний ключ между модулями — только в сторону ядра. Прикладные модули ссылаются друг на друга по id без внешнего ключа.

## Выборки

Поля для чтения описывает константа в отдельном файле, а не объект в месте запроса.

- Файл `infrastructure/<модель>.select.ts`, константа `<МОДЕЛЬ>_<НАЗНАЧЕНИЕ>_SELECT`.
- Тип сверяется с моделью через `satisfies Prisma.<Модель>Select`: опечатка в имени поля не скомпилируется.
- Тип результата выводится из выборки, а не пишется руками.
- В запросе — только константа: `findMany({ select: INVOICE_CARD_SELECT })`.

```ts
export const INVOICE_CARD_SELECT = {
    id: true,
    number: true,
    state: true,
    issuedAt: true,
} satisfies Prisma.InvoiceSelect;

export type InvoiceCard = Prisma.InvoiceGetPayload<{ select: typeof INVOICE_CARD_SELECT }>;
```

## Повторяющееся условие

Условие `where`, которое повторяется в нескольких запросах (например «действующие счета»), — константа рядом с выборками с проверкой `satisfies Prisma.<Модель>WhereInput`.

## Выборка и ответ

Если ответ повторяет выборку, в файле DTO стоит проверочная строка: она сравнивает типы в обе стороны и ломает компиляцию при расхождении.

```ts
true satisfies [InvoiceCard] extends [Invoice.Card] ? ([Invoice.Card] extends [InvoiceCard] ? true : false) : false;
```

Если ответ отличается — вычисляемое поле, поле из связи, склейка — его собирает маппер `presentation/mappers/<модель>.mapper.ts`. Маппер возвращает объект-литерал: только так компилятор видит лишние и недостающие поля. Сервис маппер не вызывает.

## Репозиторий

Нужен только вместе с entity (`nestjs/layers.md`).

- Один репозиторий на entity, а не на таблицу. Связанные записи загружаются и сохраняются вместе с entity.
- Методы: загрузка (`findBy…`, `lockBy…`, `holdBy…`), `add(entity)`, `save(entity)`, удаление (`remove(entity)`, `removeBy…`). Запросов для экранов нет.
- `add` отдельно от `save` — когда вставка отличается от сохранения. Загрузка, которая создаёт запись при её отсутствии, — `lockBy…OrAdd`.
- `addOrFind(entity)` — вставка сущности с id от клиента: при повторе возвращает уже созданную. Совпадает ли повтор с первым вызовом, решает entity.
- `addOrFindActive(entity)` — вставка сущности, уникальной среди действующих (действующая подписка, открытая смена), с id от сервера. При повторе возвращает действующую. Если в ключ уникальности входят не все поля, сервис отдаёт повтор entity на сверку. Уникальность держит частичный уникальный индекс (`schema.md`).
- Запись, уникальная по ключу, заменяется в одной транзакции: `removeBy…(ключ)`, затем `add(entity)`. Что два одновременных запроса не дойдут до вставки оба, обеспечивает правило выше по сценарию — и оно названо в описании PR.
- Ошибку нарушения уникальности распознаёт одна функция `isUniqueViolation` из `src/shared/db`. Вызывается вне транзакции: после ошибки транзакция PostgreSQL уже прервана.
- Наружу — только entity, типы Prisma не выходят.
- Строка базы и состояние entity сверены проверочной строкой типов.

### Хранилище без entity

Если вся операция — один атомарный оператор и между чтением и записью ничего не решается (счётчик, взятие жетона), entity не заводится.

- Порт `ports/<предмет>.repository.ts`, метод назван по действию: `CounterRepository.increment`.
- Метод принимает значения и правило из `domain/`, отдаёт исход. Что с исходом делать, решает `domain/` или сервис.
- Других операций в таком порту нет. Как только между чтением и записью появляется решение — это entity и обычный репозиторий.

## Сырой SQL для чтения

Когда чтение не выразить выборкой одним запросом: обход дерева, объединение разнородных строк, запрос с проверкой плана.

- Порт `ports/<что>-queries.port.ts` (класс `…Queries`), реализация `infrastructure/prisma/<что>-queries.ts`. `application/` сырой SQL не пишет.
- Текст запроса — отдельная экспортируемая функция, возвращающая `Prisma.sql`: по ней тест получает план.
- Параметры подставляет только `Prisma.sql`. Склейки строк нет.
- Таблицы и типы названы со схемой PostgreSQL. Значение enum приводится к тексту в самом запросе: `state::text`.
- Тип строки объявлен рядом с запросом, поля названы как колонки, и в нём только колонки, которые читает маппинг.
- Наружу порт отдаёт типы `domain/`, а не строки.
- Совпадение типа строки с запросом компилятор не проверит: поля, которые порт отдаёт наружу, сверяет e2e сценария, сравнивая результат целиком.

## Проверяется автоматически

- `tsc`: поля выборки есть в модели; код не читает поле вне выборки; выборка совпадает с DTO и строка с entity — где стоит проверочная строка; маппер не теряет и не добавляет полей.
- `lint-roles`: `new PrismaClient()` вне `src/shared/db`.
- `table-ownership`: модель используется только своим модулем; `shared/` не обращается к моделям; справочные представления только читаются.
- Старт приложения: `DbService` не запускается, если пояс сессии не UTC.
- e2e пояса сессии: при поясе базы, отличном от UTC, сессии приложения и миграций остаются в UTC; записанный момент читается тем же; свои `options` из адреса сохраняются.

## Не проверяется

- Объект `select` прямо в запросе.
- Что у выборки, уходящей в ответ, есть проверочная строка или маппер.
- Что тип строки сырого запроса совпадает с колонками.
- Секретные поля в выборке для ответа.
- Чужая таблица в сыром SQL.
- `SET TIME ZONE` и выражения, зависящие от пояса, в сыром SQL и миграциях; расхождение строк закрепления пояса в `prisma.config.ts` и `src/shared/db`.
