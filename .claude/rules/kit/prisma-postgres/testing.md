# Тесты с базой

Общие правила — `base/testing.md` и `nestjs/testing.md`. Здесь — то, что добавляет база.

## Что чем проверять

- **Запрос, который обязан идти по индексу**, — e2e на данных, созданных в самом тесте: тест читает план через `planOf`. Проверяется то, что устойчиво между прогонами и версиями PostgreSQL: по индексу, не полным просмотром, не больше N строк. Индекс называется по имени там, где у планировщика нет выбора.
- **Одновременность** — e2e с принудительным пересечением через `runOverlapped`: первая транзакция остаётся открытой, пока вторая не встанет на замок. Два вызова через `Promise.all` могут пройти по очереди и ничего не доказать.
- **Запрос, который не отвечает**, — `holdLock` держит замок, пока тест его не отпустит; отпускается в `finally`. Такой тест ждёт настоящий предел транзакции и получает свой таймаут.

## Оснастка — роли kit

| Роль | Что умеет |
| --- | --- |
| `cleanDatabase` | очищает базу перед тестом; работает только при `NODE_ENV=e2e`. Таблицы, защищённые триггером от изменений, перечислены в нём: очистка выключает триггер на своё время |
| `planOf` | план запроса: какие таблицы прочитаны, каким способом и сколько строк |
| `runOverlapped` | две транзакции, которые обязаны пересечься |
| `holdLock` | удерживает замок строки до сигнала теста |

Пока в схеме нет моделей, тесты `src/shared/db` работают на временной таблице и удаляют её в `afterAll`: иначе CI найдёт расхождение схемы с миграциями.

## Параллельные сессии

e2e идут на своей временной базе: `DATABASE_URL` из окружения сильнее `.env.e2e`.

## Проверяется автоматически

- `cleanDatabase` отказывается работать вне `NODE_ENV=e2e`.

## Не проверяется

- Что у критичного запроса есть проверка плана.
- Что одновременность проверена через пересечение, а не через `Promise.all`.
